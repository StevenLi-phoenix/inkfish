## 关键决策落地

### Cache token 双路径兼容
- 测试同时覆盖 `prompt_tokens_details.cached_tokens`（新版 openai SDK）和 `prompt_cache_hit_tokens`（legacy model_extra）。
- 实际 live 测试：短 prompt (~44 tokens) 不触发缓存（DeepSeek 阈值 ~1024 tokens）。**P0 D7 的 character persona 块需 ≥ 1024 tokens 才能验证 cache 命中**——这影响 D10 验证策略。

### Retry 不变量
- `call_with_retry` 永不抛错——3 次 attempt 全失败 → `fallback_do_nothing()`。
- 每次 attempt 产生一条 LLMLogRow（含失败），最终 fallback 再加一条合成 log，标记 `error="all_attempts_failed"`、`finish_reason="fallback_do_nothing"`。
- 4 条 log（3 attempt + 1 fallback）验证完整审计链。

### 温度衰减
- Attempt 1: 0.7, Attempt 2: 0.6, Attempt 3: 0.5（验证 `test_temperature_decays_across_attempts`）。
- Attempt 2/3 的 user prompt 加纠错 prefix："上次响应非法 JSON: {error}. 只输出 JSON. 不要 markdown 围栏. 不要散文。"

### Cost 公式
```
cost = (prompt_tokens - cached_tokens) * input_rate
     + cached_tokens * cached_input_rate
     + response_tokens * output_rate
```
v4-pro 折扣价：`input = 0.075/M`, `cached_input = 0.0075/M`, `output = 0.125/M`.

## 实施过程中的修复

1. **B023 closure 变量绑定 bug**：内层 `_network_call` 闭包通过引用捕获 `_user`/`_temp`。修复：转为 default-argument binding。
2. **`max_tokens=50` 导致空 content**：DeepSeek v4-pro 用 extended reasoning tokens 消耗 budget。Live 测试改用 `max_tokens=200`。
3. **Tenacity sleep 让测试变慢**：429/connection 错误测试因真实 exponential backoff 跑 11-20s。修复：`monkeypatch.setattr(time, "sleep", lambda _: None)`。

## 与计划的偏差

- **2 个 live tests** 而非 1 个（subagent 主动加了 cache-hit 检测）。
- Cache hit 在短 prompt 下未命中是预期行为（DeepSeek 阈值 ~1024 tokens），D10 用完整 character persona prompt 才能复现 cache 命中。已记入风险——D7 prompt builder 要保证 persona 块 ≥ 1024 tokens。
