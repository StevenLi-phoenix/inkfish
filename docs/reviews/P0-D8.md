## 关键不变量验证

- **Scheduler 永不抛错**：char_lin tick=2 全 3 次 attempt 返回空 content，`call_with_retry` 返回 `DO_NOTHING` fallback；scheduler 继续；tick 2 仍产 5 个 ActionRow ✓
- **R2 风险（DeepSeek JSON 偶尔丢内容）真实出现**：14 个 log row 中 4 个是失败/retry/fallback。比例 ~29%（超 5% 目标）——D10 需重点观察并可能要调 prompt 或 retry 策略。
- **MOVE_TO 鉴权**：未知 target 地点的 MOVE_TO 被静默忽略（test 9 验证），不污染状态。

## 实施过程中的修复

1. **`advance_time` double-increment**：原版 `advance_time(hours)` 同时 +tick_id +sim_time。scheduler 已直接赋值 `world.tick_id = tick_id`，再调 advance_time 导致 +1 越过目标。修复：scheduler 直接用 `timedelta` 加 sim_time，不调 advance_time。
2. **`AliasChoices` for Settings**：pydantic-settings v2 不支持嵌套 Config + model_config。改用 `Field(validation_alias=AliasChoices("INKFISH_DB_URL", "db_url"))`——idiomatic 且测试隔离工作。

## 关注点（待 D10 处理）

**R2 真实发生**：tick=2 char_lin 三次连续返回空 content。可能原因：
- DeepSeek JSON 模式 + 长 prompt 概率性产 `finish_reason=length` 截断
- 角色 persona 长 + 多个其他角色的感知块 → response 没够 tokens
- 当前 `max_tokens=800` 可能不够

**D10 待调**：观察 10-tick 完整跑的失败比例；可能上调 `max_tokens=1200` 或精简 perception block。
