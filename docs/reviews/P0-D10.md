## 异常分析

### 1. char_zhao tick=4 fallback DO_NOTHING（1/50）

3 attempts 全 truncated JSON（`finish_reason=stop` 但 content 不完整，最后一次刚好在 `"target"` 字段截断）。重试 + fallback 设计 work——产生了合法的 DO_NOTHING 替代 action。

根因不是 length（max_tokens 充足），是 v4-pro **偶尔输出不完整 JSON**（约 1.8% 概率）。对应 04-build §Q4：可能需要在 user prompt 加更明确的"必须完整闭合 JSON"提示，或检测到接近完整时 client-side 自动补 `}`。

### 2. Tick 3+ cache hit 掉到 54%

Tick 1-2 cache 92.7-93.1%（完美），tick 3 起骤降到 54% 稳定区。
**根因猜测**：reset(4) 操作可能让 DeepSeek 端 cache prefix 在某种意义上失效（虽然 prompt 内容字节相同），或更可能是 sim_time 变化让 perception block 部分 diff，但奇怪的是 tick 1-2 也有 sim_time 变化却 cache 仍高。

需 D11 重跑（无 reset 的全程一次性 10-tick）确认是否 reset 引起 cache 碎片化。如果是，P1 / P5 fork 设计需考虑这点。
