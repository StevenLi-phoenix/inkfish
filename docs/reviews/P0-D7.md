## 关键决策落地

### 三块结构与 cache 边界
- Block [1] 人设：仅用 `id, name, age, mbti, personality, background, routine`（稳定字段），不含 `tick_id / sim_time / current_mood / current_location`。
- Block [2] 记忆：P0 固定为 `_MEMORY_STUB` 常量字符串，所有角色所有 tick 字节完全相同。
- Block [3] 感知：每 tick 不同（`tick_id + sim_time + location + others + current_mood`）。

### DeepSeek JSON 模式要求
- 系统 prompt 含 `"json"` 字面量（满足 `response_format={"type": "json_object"}` 前提条件）。
- 用户 prompt 末尾固定追加 `"请以 json 对象输出本回合的 action。"`（同样含 `"json"`）。
- `test_full_prompt_includes_word_json` + `test_load_system_prompt_returns_nonempty_with_word_json` 双重验证。

### Routine key 排序
`sorted(character.routine.items())` 消除 Python dict 顺序非确定性，`test_routine_key_order_deterministic` 验证。

### 系统 prompt 不含角色数据
`test_system_prompt_no_character_specific_data` 检查 5 个 char_id 均不出现在系统 prompt 中——改动系统 prompt 不能引入角色特定数据。

### 黄金快照机制
- 首次运行无 golden 文件时，写入当前输出并 `pytest.skip`。
- 后续运行对比 byte-for-byte，格式一变立即失败，保护 DeepSeek 前缀缓存。
